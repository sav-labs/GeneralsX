# Battle FPS Profiling: Dynamic Lights and Soft Particles

> [!NOTE]
> **AI-Generated Content Disclosure**: This note was generated by an AI coding agent to support
> on-machine profiling of battle-scene frame rate.

## Goal

Isolate what drives battle-scene FPS lag on the deploy machine, specifically the two leading
suspects:

- **Dynamic lights** (`W3DEffectLights`, `SECTION_EFFECT_LIGHTS` PerfStats scope) — coloured lights
  from explosions, fires, muzzle flashes, missile exhausts and superweapons.
- **Soft particles** (DXVK depth-aware particle softening).

Both are render-only. They do not touch gameplay logic or determinism, so toggling them is safe for
a profiling run and cannot desync a replay.

## Diagnostic knobs

### `-dynamicLights <off|low|high>` (CLI flag)

Overrides the `Options.ini` `DynamicLights` quality for a **single run** without editing
`Options.ini`. Accepts `off` / `low` / `high` (case-insensitive) and the numeric forms `0` / `1` / `2`.

- `off` — only the lights the game data asks for (retail behaviour), no effect lights.
- `low` — explosion, muzzle-flash and superweapon lights, lit on the terrain vertices.
- `high` — also fires and missile exhausts, more simultaneous lights, smooth ground light pool.

Mechanism: the flag calls `OptionPreferences::setDynamicLightsOverride()`, which
`OptionPreferences::getDynamicLightsMode()` honours ahead of the `Options.ini` key. `W3DEffectLights`
reads that at scene init, so the override applies for this run only. It lives in shared `Core`
(`CommandLine.cpp`, `OptionPreferences.cpp`), so it works identically in GeneralsXZH and GeneralsX.

### `DXVK_SOFT_PARTICLES` (environment variable)

Soft particles are **on** by default; set `DXVK_SOFT_PARTICLES=0` to turn them off for a run. No code
change is needed — set the env var per-process.

## Instrumentation already wired

- `[PERF]` summary prints per-run FPS and section timings.
- `SECTION_EFFECT_LIGHTS` PerfStats scope reports the effect-lights cost inside that summary.
- `[LIGHTS]` line at scene init echoes the active `DynamicLights` mode and light count.

## Command matrix (Windows, run from the ZH game dir)

Base command:

```
GeneralsXZH.exe -skirmish "Maps\Tournament Desert\Tournament Desert.map" 1 -side America -aiside China -seed 12345 -camtest 10 battle 60 -perf -win
```

Four variants isolate the suspects; each writes to its own log. Run them in a PowerShell prompt from
the game directory.

### A) Baseline — DynamicLights=High, soft particles on

```powershell
Remove-Item Env:\DXVK_SOFT_PARTICLES -ErrorAction SilentlyContinue
& .\GeneralsXZH.exe -skirmish "Maps\Tournament Desert\Tournament Desert.map" 1 -side America -aiside China -seed 12345 -camtest 10 battle 60 -perf -win -dynamicLights high 2> perf_A_baseline.log
Get-Content perf_A_baseline.log | Select-String '\[PERF\]'
```

### B) No soft particles — DynamicLights=High, soft particles off

```powershell
$env:DXVK_SOFT_PARTICLES = "0"
& .\GeneralsXZH.exe -skirmish "Maps\Tournament Desert\Tournament Desert.map" 1 -side America -aiside China -seed 12345 -camtest 10 battle 60 -perf -win -dynamicLights high 2> perf_B_nosoftparticles.log
Remove-Item Env:\DXVK_SOFT_PARTICLES
Get-Content perf_B_nosoftparticles.log | Select-String '\[PERF\]'
```

### C) Low dynamic lights — DynamicLights=Low, soft particles on

```powershell
Remove-Item Env:\DXVK_SOFT_PARTICLES -ErrorAction SilentlyContinue
& .\GeneralsXZH.exe -skirmish "Maps\Tournament Desert\Tournament Desert.map" 1 -side America -aiside China -seed 12345 -camtest 10 battle 60 -perf -win -dynamicLights low 2> perf_C_lowlights.log
Get-Content perf_C_lowlights.log | Select-String '\[PERF\]'
```

### D) Both off — DynamicLights=Off, soft particles off

```powershell
$env:DXVK_SOFT_PARTICLES = "0"
& .\GeneralsXZH.exe -skirmish "Maps\Tournament Desert\Tournament Desert.map" 1 -side America -aiside China -seed 12345 -camtest 10 battle 60 -perf -win -dynamicLights off 2> perf_D_bothoff.log
Remove-Item Env:\DXVK_SOFT_PARTICLES
Get-Content perf_D_bothoff.log | Select-String '\[PERF\]'
```

## Reading the results

Compare the `[PERF]` FPS summary across A/B/C/D:

- A vs B isolates the soft-particle cost (same lights, particles toggled).
- A vs C vs D isolates the dynamic-light cost (particles held, light quality stepped down).
- D is the floor: both suspects off.

Within each log, the `SECTION_EFFECT_LIGHTS` line in the `[PERF]` summary attributes the effect-light
time directly, so even a single run tells you the effect-light share of the frame.
